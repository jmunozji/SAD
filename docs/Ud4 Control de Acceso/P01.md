# Práctica 4.1: Protección del Gestor de Arranque GRUB2 con Contraseña

!!! note "Datos de la Práctica"
    * **Módulo:** Seguridad y Alta Disponibilidad (SAD - 0378)
    * **Unidad Didáctica:** UD4 - Control de Accesos
    * **Requisitos:** Sistema operativo Linux (Ubuntu Desktop/Server o Debian) en entorno físico o máquina virtual (VirtualBox / KVM / GNS3) con privilegios de superusuario (`sudo`).

---

## 1. Objetivos

* Comprender el impacto de seguridad de un gestor de arranque no protegido frente a un atacante con acceso físico o consola local.
* Analizar la vulnerabilidad de escalada implícita a `root` mediante la inyección del parámetro `init=/bin/bash` en la línea de comandos del kernel.
* Generar de forma segura resúmenes de contraseñas mediante el algoritmo de derivación de clave **PBKDF2** en GRUB2.
* Configurar usuarios y contraseñas cifradas en los archivos de plantilla de `/etc/grub.d/` (`40_custom` o `00_header`).
* Diferenciar el comportamiento entre bloqueo total de arranque y uso del parámetro `--unrestricted` para permitir el arranque estándar restringiendo solo la edición.
* Aplicar los cambios en la configuración activa mediante `update-grub` y verificar la efectividad de las contramedidas.

---

## 2. Introducción Teórica: La Brecha del Menú de Arranque

Cuando un sistema operativo Linux inicia, el firmware de la placa base (BIOS/UEFI) pasa el control al cargador de arranque **GRUB2** (*Grand Unified Bootloader*). Si el menú de GRUB2 no está protegido por contraseña, cualquier persona con acceso al teclado durante el encendido puede alterar la secuencia de arranque.


> [ Menú de GRUB2 ] ──> Pulsa 'e' ──> Añade 'init=/bin/bash' ──> Ctrl+X ──> Consola Root de emergencia (Sin Clave)


### El Ataque de Inyección `init=/bin/bash`
1. Al encender el equipo, el usuario pulsa la tecla **`e`** para editar interactivamente la entrada del menú.
2. Localiza la línea que carga el kernel Linux (`linux /boot/vmlinuz...`) y sustituye los parámetros finales (como `ro quiet splash`) por:
   ```text
   rw init=/bin/bash
   ```
3. Pulsa `Ctrl + X` o `F10` para arrancar.
4. **Resultado:** El kernel inicia montando la raíz en lectura/escritura (`rw`) y sustituye el proceso de inicialización estándar (`systemd`) por una consola de comandos `bash`. El atacante obtiene acceso inmediato como **`root` sin que el sistema le pida ninguna contraseña**, permitiéndole ejecutar `passwd root` o manipular cualquier fichero del disco.

## 3. Desarrollo Paso a Paso de la Práctica

### Preparar el entorno

Usaremos una máquina virtual en VirtualBox de Ubuntu Server 18.04. No necesitamos una más moderna. No intentes hacerlo en GNS3 porque la conexión a las máquinas se hace por Telnet y no verás las entradas del GRUB 

Antes de nada crea un “Instantanea” de tu máquina virtual en VirtualBox por si corrompes accidentalmente el GRUB y no puedes entrar en la máquina. 

!!! Importante
       Si trabajamos directamente sobre la ventana de la máquina virtual no podremos copiar y pegar lo que veremos más adelante que imposibilita la práctica. Así que te recomiendo que accedas a la máquina por ssh desde un terminal del host, que si te lo permitirá.

       Para ello configura la interfaz de red en VirtualBox como "Adaptador puente"

       Si es necesario instala "openssh-server"

       Desde un terminal del host accede a la máquina virtual con `ssh admin01@192.168.1.43` (Modifica los valores adecuadamente)

Por defecto el menú del GRUB está deshabilitado y no lo veremos. Haremos estos cambios para poder verlo. 

Edita el fichero `etc/default/grub` y asegurate de tener estas 3 líneas con estos valores: 

```
GRUB_DEFAULT=0  
GRUB_TIMEOUT_STYLE=menu  
GRUB_TIMEOUT=10 
```

Actualiza el grub con `$ sudo update-grub2` y reinicia la máquina. Ahora deberías ver el menú de GRUB con una cuenta atrás de 10 seg 

Ahora vamos a incluir una entrada manual de GRUB para que nos muestre un segundo sistema operativo, aunque no exista.  Para ello editaremos el fichero `/etc/grub.d/40_custom` y lo dejaremos así. Este fichero incluye las entradas de GRUB que no detecta él automáticamente. 

```sh
#!/bin/sh 
exec tail -n +3 $0 
# This file provides an easy way to add custom menu entries.  Simply type the 
# menu entries you want to add after this comment.  Be careful not to change 
# the 'exec tail' line above. 
menuentry "Windows 11 (ficticio)" { 
   echo "Arrancando Windows ficticio..." 
   sleep 5 
} 
```
 

Vuelve a actualizar el grub y reinicia. Ahora deberías ver una entrada para tu linux y otra de Windows 11, que si seleccionas mostrará “Arrancando Windows ficticio”, esperará 5 min y volverá al menú. .

### Tarea 1: Demostración del Ataque de Inyección (Entorno de Laboratorio)

2. En la pantalla de inicio del menú de GRUB2, pulsa rápidamente la tecla **`e`**.
3. Desplázate con las flechas del teclado hasta la línea que comienza por `linux`.

### Tarea 2: creación de un usuario GRUB con contraseña en texto plano

Antes de empezar a modificar la configuración del Grub tenemos que tomar ciertas precauciones. Para ello antes de iniciar todo el proceso realizaremos copias de seguridad de la totalidad de archivos que vamos a modificar. Para hacer las copias de seguridad abrimos una terminal y ejecutamos los siguientes comandos:

```sh
sudo cp /boot/grub/grub.cfg ~/grub.cfg.old
sudo cp /etc/grub.d/00_header ~/00_header.old
sudo cp /etc/grub.d/10_linux ~/10_linux.old
sudo cp /etc/grub.d/30_os-prober ~/30_os-prober.old
```

Estos tres comandos generarán una copia de seguridad de los archivos grub.cfg, 00_header, 10_linux y 30_os_prober en nuestra partición home.

Para definir los usuarios y las contraseñas de los usuarios, que podrán usar la línea de comandos del grub, y ejecutar y editar las entradas del grub, tenemos que abrir una terminal y ejecutar el siguiente comando:

```sudo nano /etc/grub.d/40_custom```

Una vez abierto el editor de textos nano, vamos al final del archivo y tenemos que añadir la lista de usuarios y de contraseñas añadiendo el siguiente texto:

```
set superusers="root"
password root 1234
OF
```

Como se puede ver en este texto hemos definido 1 usuario que hemos llamado "root". Tendrá la contraseñas 1234. Como ves las contraseñas están aún en texto plano. Ya lo solucionaremos más adelante.

Guarda los cambios, ejecuta un `sudo update-grub2` y reinicia.

Intenta arrancar alguno de los sistemas operativos, pon un usuario y contraseña incorrectos e intenta arrancarlo. No debe dejarte. Luego pon usuario y contraseña correctos y arranca tu linux. Si deberías poder. 

### Tarea 2: Generación del Hash Cifrado PBKDF2 de la Contraseña

Para evitar guardar contraseñas en texto claro dentro de los ficheros de configuración de GRUB2, la herramienta incluye un generador de resúmenes mediante el algoritmo **PBKDF2** (*Password-Based Key Derivation Function 2*) con HMAC-SHA-512. La utilidad nos permitirá generar la contraseña cifrada y luego la podremos incluir en el fichero 00_header.

2. Ejecuta la utilidad de cifrado de contraseñas de GRUB2:
   ```bash
   grub-mkpasswd-pbkdf2
   ```
3. Introduce la contraseña que deseas asignar al superusuario de GRUB2 (por ejemplo: `1234`) y confírmala.
4. Observa la salida generada en pantalla:
   ```text
   Introduzca la contraseña: 
   Reescriba la contraseña: 
   El hash PBKDF2 de la contraseña es grub.pbkdf2.sha512.10000.C8F9E0A...[CADENA_HEXADECIMAL_LARGA]
   ```
5. **Copia la cadena completa** comenzando desde `grub.pbkdf2.sha512...`. La necesitarás en la siguiente tarea.

### Tarea 3: Configuración del Superusuario y Contraseña en `/etc/grub.d/40_custom`

!!! tip "Nunca edites directamente `/boot/grub/grub.cfg`"
    El archivo `/boot/grub/grub.cfg` es generado automáticamente por el comando `update-grub`. Cualquier cambio manual en él se sobrescribirá en la siguiente actualización del kernel. Los cambios deben realizarse en los archivos de plantilla ubicados en `/etc/grub.d/`.

1. Abre el archivo de personalización `/etc/grub.d/40_custom` utilizando un editor de texto con privilegios de superusuario (`sudo`):
   ```bash
   sudo nano /etc/grub.d/40_custom
   ```
2. Al final del archivo (sin modificar las líneas de encabezado existentes), añade las siguientes instrucciones:
   ```bash
   set superusers="root"
   password_pbkdf2 root TU_CADENA_HASH_PBKDF2_COMPLETA
   ```
   *(Sustituye `TU_CADENA_HASH_PBKDF2_COMPLETA` por el valor copiado en la Tarea 2).*

3. Guarda los cambios y sal (`Ctrl + Y` en nano). Actualiza GRUB.

### Tarea 4: Control del Comportamiento del Arranque (Opciones de Bloqueo)

Por defecto, definir `set superusers` bloquea **todas** las entradas del menú de GRUB2, exigiendo usuario y clave incluso para arrancar el sistema operativo normal.

#### Permitir arranque normal sin clave, pero bloquear edición y modo recuperación
Si deseas que el equipo encienda y cargue el sistema operativo automáticamente sin pedir contraseña, pero que **SÍ solicite credenciales si alguien intenta pulsar 'e' (editar) o ingresar al modo de recuperación**. Asegúrate de que las entradas del kernel en `/etc/grub.d/10_linux` contengan el parámetro `--unrestricted`.

Veamos como añadir ese `--unrestricted`. Abrimos una terminal y ejecutamos el siguiente comando:

`sudo nano /etc/grub.d/10_linux`

Una vez abierto el editor de textos, localizamos las siguientes lineas:

```
echo "menuentry '$(echo "$title" | grub_quote)' ${CLASS} \$menuentry_id_option 'gnulinux-$version-$type-$boot_device_id' {" | sed "s/^/$submenu_indentation/"

else

echo "menuentry '$(echo "$os" | grub_quote)' ${CLASS} \$menuentry_id_option 'gnulinux-simple-$boot_device_id' {" | sed "s/^/$submenu_indentation/"
```

Una vez localizadas las lineas, las tenemos que modificar de la siguiente manera, añadiendo `--unrestricted`después de ${CLASS}

```
echo "menuentry '$(echo "$title" | grub_quote)' ${CLASS} --unrestricted \$menuentry_id_option 'gnulinux-$version-$type-$boot_device_id' {" | sed "s/^/$submenu_indentation/"

else

echo "menuentry '$(echo "$os" | grub_quote)' ${CLASS} --unrestricted \$menuentry_id_option 'gnulinux-simple-$boot_device_id' {" | sed "s/^/$submenu_indentation/"
```

Una vez añadidas las modificaciones, guardamos los cambios realizados en el fichero de configuración. Abrimos una terminal y actualizamos la configuración del grub aplicando el siguiente comando:

`sudo update-grub2`

En estos momentos cualquier usuario podrá arrancar el sistema operativo principal sin tener que introducir ningún usuario ni contraseña. Compruébalo reiniciando. Trata de entrar en Windows 11 y comprueba cómo te pide la contraseña. Ponle una incorrecta y comprueba cómo no accede. Ahora entra en Ubuntu y comprueba como no te pide contraseña.

### Tarea 5: Regeneración de la Configuración y Verificación Final

1. Una vez editado `/etc/grub.d/40_custom`, aplica los cambios regenerando el archivo `/boot/grub/grub.cfg`:
   ```bash
   sudo update-grub
   ```
   *(O mediante la sintaxis directa: `sudo grub-mkconfig -o /boot/grub/grub.cfg`)*.

2. Verifica que los parámetros de superusuario se han transferido correctamente al archivo final:
   ```bash
   sudo grep -E "superusers|password_pbkdf2" /boot/grub/grub.cfg
   ```
   Comprueba que aparece la línea `set superusers="root"` y la clave hash asociada.
3. **Prueba de Campo (Verificación):**
    * Reinicia la máquina virtual: `sudo reboot`.
    * En el menú de inicio de GRUB2, intenta pulsar la tecla **`e`** para editar la entrada.
    * **Resultado esperado:** GRUB2 detendrá la acción y mostrará una pantalla pidiendo `Introduzca el nombre de usuario:` y `Contraseña:`.
    * Introduce `root` y la clave en claro que asignaste. Comprueba que solo tras la validación correcta se habilita la edición del menú.
    * Intenta pulsar la tecla **`c`** para acceder a la consola interactiva de GRUB y verifica que también requiere autenticación.
